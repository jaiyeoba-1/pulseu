# PulseU

**A student life coach that rebuilds tonight and tomorrow around the day you actually had.**

Built in 24 hours at HackWesTX VII.

## The idea

Most productivity apps plan around the day you *expected* to have. They'll tell a student running on five hours of sleep, who hasn't eaten since breakfast, to knock out four more hours of studying.

PulseU reads the day that actually happened and replans around it — measured against that student's own 30-day baseline, not a generic standard.

## How it works

**1. Morning check-in.** Sleep, energy, mood, and today's tasks. No AI — just a form.

**2. Through the day.** Four buttons log timestamped events: studied, break, meal, energy check-in. The dashboard shows today's energy against the student's own 30-day average.

**3. End School Day.** A deterministic strain score (0–100) is computed from weighted behavioral inputs. Gemini then explains that score and rebuilds the evening — what to finish tonight, what to defer, a stop time, and tomorrow reorganized around whatever got pushed.

## Architecture

**The score is math, not a model.** `lib/score.ts` weighs sleep deficit, energy decline across the day, longest study stretch without a break, missed meals, total workload, and deviation from the personal baseline. It is deterministic and auditable.

**Gemini explains, it never computes.** The model receives the score and its contributing factors and returns structured JSON. A system instruction forbids it from recalculating the number or inventing tasks the student didn't enter. Calls retry with exponential backoff, fall back across model versions, and serve the last matching cached plan if the API is unavailable.

**Why a time-series database.** `student_events` is a TimescaleDB hypertable. `daily_stats` is a continuous aggregate that rolls events into per-day statistics automatically. The headline query cross-joins today's live events against the 30-day aggregate to produce the personal baseline comparison — cheap because the rollup already exists.

## Project structure

- `app/page.tsx` — single-page UI: check-in, dashboard, recovery
- `app/api/checkin/route.ts` — morning form
- `app/api/events/route.ts` — event logging and today's energy curve
- `app/api/baseline/route.ts` — today vs 30-day baseline, the core query
- `app/api/recovery/route.ts` — scoring and Gemini
- `lib/db.ts` — Postgres pool
- `lib/session.ts` — Auth0 identity to internal user id
- `lib/score.ts` — deterministic strain score
- `lib/gemini.ts` — Gemini client with retry and model fallback
- `db/schema.sql` — tables, hypertable, continuous aggregate
- `db/seed.py` — generates 30 days of realistic history
- `proxy.ts` — mounts Auth0 routes for Next.js 16

## Running locally

Clone, then `npm install`. Create a `.env.local` with `DATABASE_URL`, `GEMINI_API_KEY`, `APP_BASE_URL`, `AUTH0_DOMAIN`, `AUTH0_CLIENT_ID`, `AUTH0_CLIENT_SECRET`, and `AUTH0_SECRET` (generate the last with `openssl rand -hex 32`).

Then run `psql "$DATABASE_URL" -f db/schema.sql`, seed a demo user with `python3 db/seed.py "auth0|your-user-id"`, and start with `npm run dev`.

## A note on the data

The 30 days of history in the demo is generated by `db/seed.py`. A personal baseline can't be demonstrated on day one, so we simulate a month of realistic student behavior — including deliberately rough days with poor sleep and no breaks — so the comparison has something to compare against. Real events flow through the identical pipeline.

The strain score is transparent and auditable, not clinically validated. The UI calls it a "daily capacity indicator," never a diagnosis. PulseU is a wellness and productivity tool; it does not diagnose or treat anything.
